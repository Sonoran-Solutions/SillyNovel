# M3.3 PR D: Gate C readiness scripts

Two scripts for the [Gate C record](../../../docs/GATE_C_RECORD_TEMPLATE.md). Neither changes the runtime.

## `demo.mjs`: the seven demonstrations, SYNTHETIC

It runs on the disposable pinned SillyTavern 1.19.0 host (`createHarness` from `../m2-director/harness.mjs` refuses any other source and clones it into an owned `sn-*` root under TMPDIR). It uses the fake ComfyUI `tests/fixtures/m3-comfy-endpoint.mjs` on an ephemeral loopback port and the synthetic text endpoint on 8128. Port 8128 must be free. Demonstrations, in order: `new-background`, `cache-hit`, `rejected-candidate`, `policy-refusal` (the fixture's synthetic refusal, J7), `timeout` (a held job, the real 120 s wait, then the late image), `cancelled-or-stale` (Cancel; a newer scene; a reload and takeover), `usage-limit` (five, the sixth refused, still five after a reload).

```
SN_PLAYWRIGHT_MODULE=<playwright>/index.mjs node tests/probes/m3-gate-c/demo.mjs --proof-loopback <pinned-host-root>   # coordinator: automated, asserted
SN_PLAYWRIGHT_MODULE=<playwright>/index.mjs node tests/probes/m3-gate-c/demo.mjs --owner <pinned-host-root> [--only id,id]   # owner: headed, Enter between steps
```

`--only` runs a subset in owner mode, and refuses a selection that leaves out a prerequisite: `cache-hit` needs `new-background` in the same run, because its hit is that run's imported result. The proof always runs all seven. Every demonstration begins with a line telling the owner to turn the session on if it is off (fresh-session demonstrations: off, then on), so a standalone `--only` run starts correctly. It writes `observations.json` (labelled SYNTHETIC) in the owned root it prints. Owner mode records what it observes against the expected changes and asserts nothing. The proof also runs the capture pipeline below on its own synthetic data.

**The 8188 guard.** The host contacts ComfyUI from its server, so every page request goes to the host's own origin and the ComfyUI address travels in the JSON body as `url`. A route on each browser context reads the body. It aborts any `/api/sd/*` request that is not one of ComfyUI's routes with exactly the fixture origin, aborts unparseable bodies there, and aborts any other host API request whose backend-address keys (`url`, `api_server`, `custom_url`, `reverse_proxy`, `server_url`, `*_endpoint` and similar) hold an http(s) address other than the fixture or the text endpoint. Every request to the host passes through the guard, and every rule matches one normalized path: lower case, one percent-decode, duplicate slashes collapsed, a trailing slash stripped. Paths that fail to decode, keep a `%`, or have a `.` or `..` segment are refused; the pinned Express routes case-insensitively and without strict routing. The text route passes only the seeded source (`chat_completion_source: 'custom'` with `custom_url` at the text fixture), since the host picks the provider from that source. Routes where the host picks an external endpoint itself are refused whatever their body says: other text backends and providers, translation, search, speech, vectors, remote tokenizers, asset downloads, content imports, and extension install, update and version. Before each demonstration it also reads the host's saved image settings and stops unless the ComfyUI URL is the fixture. The proof sets a tampered URL in the page (an unused loopback port with a sentinel listening there, never 8188) and checks that it is aborted and that neither the sentinel nor the fixture sees a request. If the shared harness fails during setup, the script stops its own descendants (a parent-PID walk over `/proc`, never by name), keeps the owned root and rethrows. **Limit:** the guard sees only requests from the browser contexts this script opens. A request from another client of the disposable host, or a host-side job not started by a page, is not covered. The disposable host listens on loopback only and is stopped at the end.

## `capture.mjs`: read-only capture of the owner's real session

**It runs on the owner's install only on the owner's word, recorded in DECISIONS first.** Without `--owner-accepts-read-only-capture` it refuses. It has no network code and never writes into the image folder. It never reads host settings or keys. A `--review` or `--ledger` file is refused if its real path is named `settings.json` or `secrets.json`, or if any directory above it holds either file (a SillyTavern user data root such as `data/<user>/`), whether given directly or through a symlink. Review files are capped at 1 MiB and the ledger JSON at 16 MiB. It reads the PNGs in the given `user/images` folder newer than `--since`, the review texts the owner copied (`--review`, repeatable) and, optionally, the JSON of the storage plugin's recovery tool (`tools/recovery.mjs backup`, then `inspect`, both outside the repository). For each file it reports name, size, SHA-256 and PNG signature. It parses ComfyUI's `prompt` metadata, the graph the backend actually ran, which the host stores unchanged, and checks it field by field against the review. It also cross-checks ledger rows against files. Every path is checked after `realpath`. The images folder must really be a `user/images` folder; in proof mode its real path must lie inside a real owned `sn-*` root. One helper, `underImages`, checks every path under the images folder, for the walk, the read and the ledger check alike. It examines each component with `lstat` and refuses any symlink, then confirms the resolved path lies inside the real images folder. Each file is opened without following a link, and ledger paths have no `..` segment. Matching is structural. The graph must be wired as the six-node workflow: the sampler's model from the checkpoint loader, its latent from the empty latent, its positive and negative from two distinct text encodes that read the checkpoint's CLIP, the decode reading the sampler and the checkpoint's VAE, and the save reading the decode. Each value is read from the node those links reach. A ledger row with a recorded result hash must hash-match its file. A file counts as matching a review only if, in addition, every field the review states and the six-node workflow carries matches. The only exceptions are a random seed (not compared), VAE and clip skip (not in that workflow), and a field the review renders as `null`. Its output holds no prompt or review text and is never overwritten (`wx`). It must lie outside the repository and the images folder, which is checked both on the path as given and on the real path through the nearest existing parent, so a symlinked parent cannot lead it inside.

```
node tests/probes/m3-gate-c/capture.mjs --owner-accepts-read-only-capture --images <data>/<user>/user/images --since <ISO> \
     --review <copied review.txt> --ledger <inspect.json> --out <new file outside the repository>
```

`--proof-loopback` accepts only an owned `sn-*` root under TMPDIR.
